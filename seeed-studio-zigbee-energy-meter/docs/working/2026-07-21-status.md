# Status — 2026-07-21

End-of-day snapshot after the first coding session. Living document; supersede
when the picture changes.

## Where we landed

**Working firmware on-bench**: XIAO nRF52840 Sense boots our Zephyr app,
enumerates as USB CDC-ACM, streams a 10 Hz sample log to the host, and
heartbeats the red LED at 1 Hz. Sample line format:

```
<inf> main: sample=42 voltage_mv=15 accumulator_total=0
```

**Toolchain + build + flash workflow proven end-to-end**: NCS v2.9.2 +
VS Code nRF Connect extension + UF2 drag-drop to the XIAO bootloader mass
storage device.

**Host-testable core logic** (`src/pulse_accumulator.{h,c}`): six pinned
behaviours (init→0, delta update, absolute-counter tracking, 32-bit HW
wrap, 48-bit total across many wraps, restore-from-persisted-total). Linked
into the firmware; also run standalone via `cd tests && make test`.

## Firmware summary

| Piece | Where | State |
|---|---|---|
| Boot / LED heartbeat | `src/main.c` | ✅ blinks 1 Hz once init passes |
| USB CDC-ACM console | prj.conf + board file | ✅ enumerates as `/dev/tty.usbmodem*` |
| SAADC on AIN0 (A0) | overlay + `read_phototransistor_mv()` | ✅ samples at 10 Hz, logs mV |
| Pulse accumulator | `src/pulse_accumulator.{h,c}` | ✅ linked, `total` logged but stays 0 (no pulse source wired yet) |

`main.c` uses the LED as a state indicator: 4 quick blinks on `main()` reach,
fast 12 Hz strobe if `usb_enable()` fails, slower 2 Hz strobe if ADC init
fails, 1 Hz heartbeat once everything's up.

## Build gotcha we hit — captured for future sessions

**Sysbuild must be OFF for this project** (unless we later enable MCUboot).
NCS 2.9.x sysbuild-without-MCUboot silently ignores
`CONFIG_FLASH_LOAD_OFFSET` — the app links at VMA `0x0` while the UF2 writes
blocks to physical `0x27000`. Vector table addresses inside the binary are
wrong, board silently hard-faults on boot, no LED, no USB, no output. Cost
us hours to diagnose. Full detail in `CONTRIBUTING.md` § Build gotchas.

**Also**: the XIAO in this project is the **Sense** variant. Correct board
target is `xiao_ble/nrf52840/sense`, not plain `xiao_ble/nrf52840`.

## What is *not* yet in place

- **Actual pulse source** — no GPIO interrupt or LPCOMP+PPI+TIMER wiring
  yet. The accumulator is present and its API is ready to be called, but
  nothing calls `pulse_accumulator_update()` — hence `accumulator_total=0`
  forever in the log.
- **Phototransistor hardware** — sensor not yet soldered to the board;
  A0 pin is floating. Voltage readings until wired will just be noise.
- **NVS persistence glue** — accumulator has a `restore()` entry point;
  no Zephyr NVS wrapper reads/writes it yet.
- **Zigbee stack** (ncs-zigbee v1.3.0 + NCS v2.9.2) — deferred until the
  hardware pipeline is proven on the bench.
- **`west.yml` manifest** — repo still expects an existing NCS install; not
  self-contained yet.
- **Z2M external converter** (JS + unit tests) — the other host-testable
  layer the design doc calls out.
- **Low-power / battery mode** — currently USB-C powered per initial phase.

## Next slices (in priority order)

1. **Wire a bench pulse source into the firmware**. Two options — pick one:
   - **Onboard button-less approach**: expose an unused GPIO as an
     interrupt-on-edge pin. Wire an external button or a signal generator
     to it. Call `pulse_accumulator_update()` on each edge. Fastest way to
     see the accumulator log actually incrementing.
   - **Threshold on the phototransistor voltage**: once the sensor is
     soldered, add software threshold detection in the sample loop —
     count crossings above/below a mV threshold. Less accurate than
     LPCOMP but proves the light-pulse → count path end-to-end without
     needing the full hardware peripheral chain.
2. **Solder the phototransistor to the board** per design doc wiring
   (thick leg → 3V3, thin leg → A0 + 47 kΩ → GND). Confirm the log
   voltage responds to torch / cover.
3. **Add NVS persistence for the accumulator total**. Zephyr NVS wrapper
   that reads the saved u64 on boot, writes it periodically or on report.
4. **Move the pulse path to LPCOMP → PPI → TIMER** for hardware counting
   during sleep. Requires nrfx configuration; hardware path — bench
   verified, no unit tests possible.
5. **Zigbee stack integration** — Metering cluster 0x0702 with
   `CurrentSummationDelivered`, ncs-zigbee v1.3.0 + NCS v2.9.2. Highest
   friction area per the design doc's Risks section.
6. **Z2M external converter + JS unit tests**. Can be developed in
   parallel with Zigbee firmware — the wire protocol is the contract.
7. **`west.yml` manifest** — make the repo a self-contained west
   workspace so contributors don't need a pre-existing NCS install.
8. **Battery-mode transition** — swap the phototransistor collector wire
   from `3V3` to `VDD` (or the equivalent tap for the design doc's
   "direct to BAT/VDD" scheme), measure sleep current, project battery
   life. Deferred until the pulse pipeline is proven.
