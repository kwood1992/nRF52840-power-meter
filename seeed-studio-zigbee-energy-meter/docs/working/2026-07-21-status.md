# Status — 2026-07-21

End-of-session snapshot. Living document; supersede when the picture changes.

## Where we landed

**End-to-end firmware pipeline confirmed on-bench**:
- XIAO nRF52840 Sense boots our Zephyr app
- USB CDC-ACM enumerates, streams a 10 Hz log to the host
- Red LED heartbeats at 1 Hz once init succeeds
- SAADC on AIN0 (A0) reads phototransistor voltage each sample (currently ~200 mV
  noise on the unwired pin; will drop/rise once the sensor is soldered)
- GPIO interrupt on D6 (P1.11) — the long-term Zigbee join / factory-reset
  button, currently doing double-duty as the bench pulse source. Each press
  counted with 5 ms software debounce and fed into `pulse_accumulator_update()`
  — same code path the eventual LPCOMP+PPI+TIMER hardware pipeline will drive,
  so it's a drop-in swap

Sample log line:
```
<inf> main: sample=445 voltage_mv=202 accumulator_total=3
```

Push the bench button on D1 and `accumulator_total` goes up. That is the whole
pulse pipeline validated end-to-end without needing the phototransistor wired.

**Host-testable core logic** (`src/pulse_accumulator.{h,c}`) still ships six
pinned behaviours; linked into the firmware **and** run standalone via
`cd tests && make test`. Green.

## Build gotchas captured

Three separate gotchas hit us during bring-up; all now documented in
`CONTRIBUTING.md` § Build gotchas and in memory. Short-form list here for
future-us to spot at a glance:

1. **Sysbuild without MCUboot silently ignores `CONFIG_FLASH_LOAD_OFFSET`** on
   NCS 2.9.x xiao_ble. App links at VMA 0x0 while UF2 targets 0x27000 →
   silent boot failure. Fix: sysbuild must be OFF.
2. **`boards/<board>.overlay` doesn't fire for fully-qualified board targets**
   (`xiao_ble/nrf52840/sense` looks for `boards/xiao_ble_nrf52840_sense.overlay`).
   Fix: use `app.overlay`, force-loaded via `EXTRA_DTC_OVERLAY_FILE` in
   `CMakeLists.txt` before `find_package(Zephyr)`.
3. **NCS 2.9.2 USB stack auto-enables USB before `main()`**, so `usb_enable()`
   from `main()` returns `-EALREADY`. Fix: treat `-EALREADY` as success.

Distinct LED failure patterns from `main.c` so USB-less bring-up debug stays
possible: fast strobe (80 ms) = CDC/USB init failed; 4 Hz strobe (250 ms) =
ADC init failed; 1 Hz strobe (500 ms) = button GPIO init failed; steady
1 Hz heartbeat once we reach the sample loop.

## What is *not* yet in place

- **Phototransistor hardware** — sensor not yet soldered. A0 pin floating,
  voltage readings are noise (~200 mV).
- **NVS persistence** — accumulator has a `restore()` entry point; no Zephyr
  NVS wrapper reads/writes it yet.
- **LPCOMP + PPI + TIMER hardware pulse chain** — bench button is the interim
  pulse source; the button-driven `bench_pulse_count` counter is deliberately
  API-compatible with what the hardware TIMER will produce.
- **Zigbee stack** (ncs-zigbee v1.3.0 + NCS v2.9.2) — deferred until the
  hardware pipeline is proven on the bench.
- **`west.yml` manifest** — repo still expects an existing NCS install.
- **Z2M external converter** (JS + unit tests).
- **Low-power / battery mode** — currently USB-C powered per initial phase.

## Next slices (in priority order)

1. **Solder the phototransistor** to the board per design doc wiring
   (thick leg → 3V3, thin leg → A0 + 47 kΩ → GND). Confirm voltage log
   responds to torch vs. cover, and that the accumulator increments when
   the voltage rises past the threshold. Retune `PHOTOTRANSISTOR_THRESHOLD_MV`
   (currently 1000 mV) if dark or bright readings sit close to it.
2. **NVS persistence for the accumulator total** — Zephyr NVS wrapper
   reads saved u64 on boot (via `pulse_accumulator_restore`), writes it
   periodically or on Zigbee report.
3. **Move the pulse path to LPCOMP → PPI → TIMER** for hardware counting
   during sleep. Replaces the software counter with the TIMER's counter
   register; `pulse_accumulator_update()` call site stays identical.
4. **Zigbee stack integration** — Metering cluster 0x0702 with
   `CurrentSummationDelivered`, ncs-zigbee v1.3.0 + NCS v2.9.2.
5. **Z2M external converter + JS unit tests**.
6. **`west.yml` manifest** — self-contained west workspace.
7. **Battery-mode transition** — swap phototransistor collector wire from
   `3V3` to `VDD`, measure sleep current, project battery life.
