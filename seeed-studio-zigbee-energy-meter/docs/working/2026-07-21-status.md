# Status — 2026-07-21

Snapshot of where the firmware sits at the end of the first coding session.
Living notes; supersede when the picture changes.

## What runs today

- **Host-testable core logic**: `src/pulse_accumulator.{h,c}` is a pure-C module
  with no Zephyr dependencies. Six behaviours are pinned by tests in
  `tests/test_pulse_accumulator.c`:
  1. `init` sets total to zero
  2. `update(hw)` advances total by the delta since the previous read
  3. Repeated `update` with the same value is idempotent (absolute HW counter, not incremental)
  4. 32-bit HW counter wrap counted correctly (unsigned subtraction)
  5. 48-bit-plus total survives many wraps past 2³²
  6. `restore(saved_total)` reloads persisted total and re-baselines to a fresh HW counter (0)

  Run with `cd tests && make test`. No toolchain beyond `cc` needed.

- **Zephyr walking-skeleton for XIAO nRF52840**:
  - `CMakeLists.txt`, `prj.conf`, `boards/xiao_ble.overlay`, `src/main.c`
  - `main.c` enables USB, waits for host DTR, then logs a heartbeat +
    `pulse_accumulator_total()` every second over USB CDC-ACM
  - **Not yet built on this machine** — the nRF Connect SDK / `west` are not
    installed here, so the CMake configuration is unverified. First real
    verification happens when the user builds & flashes.

## What is *not* yet in place

- Zigbee stack (ncs-zigbee R23 add-on) — deferred until the skeleton boots
- Actual pulse source — no GPIO / LPCOMP / PPI wiring yet
- NVS persistence glue for the accumulator
- `west.yml` manifest — currently structured as an out-of-tree app; user must
  build from an existing NCS workspace
- Z2M external converter

## Testing posture

- Pure logic → host tests via `make test` (fast iteration, no Zephyr toolchain)
- Hardware paths → verified on-bench (per the design doc; LPCOMP/PPI/radio can't be unit-tested)
- Walking-skeleton verification = plug board in, see the heartbeat log stream

## Current dev phase

Board powered via **USB-C**. Sleep-current, battery monitoring, and the
LPCOMP+PPI+TIMER hardware pulse chain are deferred. Early pulse-source
experiments can use a GPIO interrupt / button as a stand-in for the
phototransistor path.

## Items to verify on first build (unknowns from writing without a toolchain)

- Board target name: used `xiao_ble`. NCS ≥ v2.6 with hardware-model-v2 may
  want `xiao_ble/nrf52840` instead. Adjust if `west build -b xiao_ble` fails
  with a "board not found" error.
- `zephyr_udc0` label in `boards/xiao_ble.overlay` — standard on the XIAO but
  first suspect if the overlay fails to compile.
- USB VID/PID in `prj.conf` set to `0x2FE3 / 0x0100` (Nordic dev-VID placeholder).
  Fine for bench; replace before shipping.
